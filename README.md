# Container Orchestration Basics

Этот репозиторий содержит учебный проект по запуску и оркестрации контейнеров с помощью **Docker Compose** и **Docker Swarm**.  
В рамках работы были контейнеризированы микросервисы, настроен совместный запуск сервисов на одной машине, затем подготовлен кластер из нескольких виртуальных машин и развёрнут стек сервисов в Docker Swarm.

Цель проекта — на практике понять, как запускать многоконтейнерные приложения, как переносить их с одной машины на несколько узлов и как устроена базовая оркестрация контейнеров.

## О проекте

Во время выполнения проекта я последовательно прошёл путь от локального запуска микросервисного приложения через **Docker Compose** до развертывания этого же приложения в кластере **Docker Swarm**.

Сначала для каждого сервиса были написаны Dockerfile и Compose-конфигурация, после чего приложение было собрано и протестировано локально. Затем с помощью **Vagrant** были созданы виртуальные машины, из которых был сформирован кластер Swarm. После этого стек сервисов был развернут уже в распределённой среде, а доступ к части сервисов был организован через **nginx** и overlay-сеть.

Проект помог лучше понять базовые принципы контейнеризации, взаимодействия микросервисов и оркестрации контейнеров в кластере.

## Что было сделано

### Part 1. Запуск нескольких Docker-контейнеров с использованием Docker Compose
- Для каждого микросервиса был написан отдельный `Dockerfile`.
- Были описаны зависимости и команды запуска сервисов.
- Настроен `docker-compose.yml` для совместного запуска всех сервисов.
- Реализовано корректное взаимодействие сервисов между собой по внутренней сети Docker.
- Проброшены порты для доступа к:
  - `gateway service`
  - `session service`
- Выполнена сборка и запуск приложения на локальной машине.
- Проведено тестирование через Postman.
- Подтверждено, что сервисы работают корректно и тесты проходят успешно.
- В отчёте фиксировались размеры образов и результаты тестов.

Примеры команд:
`docker build -t service-name .`  
`docker images`  
`docker image ls`  
`docker compose up --build`  
`docker compose ps`  
`docker compose logs`  
`docker compose down`

Что полезно помнить:
- у каждого микросервиса свой контейнер;
- Compose поднимает все сервисы одной командой;
- сервисы внутри compose обычно обращаются друг к другу по имени сервиса.

### Part 2. Создание виртуальных машин
- Установлен и инициализирован **Vagrant** в корне проекта.
- Написан `Vagrantfile` для одной виртуальной машины.
- Настроен перенос исходного кода в рабочую директорию внутри виртуальной машины.
- Выполнен вход в виртуальную машину через консоль.
- Проверено, что проект находится в нужной директории.
- После проверки виртуальная машина была остановлена и удалена.

Примеры команд:
`vagrant init`  
`vagrant up`  
`vagrant ssh`  
`ls -la`  
`pwd`  
`vagrant halt`  
`vagrant destroy -f`

Что полезно помнить:
- Vagrant позволяет быстро поднимать одинаковые VM;
- код проекта можно пробрасывать в VM через synced folder;
- это удобная база для будущих узлов Swarm.

### Part 3. Создание простейшего Docker Swarm
- `Vagrantfile` был изменён для создания трёх машин:
  - `manager01`
  - `worker01`
  - `worker02`
- Подготовлены shell-скрипты для:
  - установки Docker,
  - инициализации Swarm,
  - подключения worker-узлов к manager.
- На менеджере выполнена инициализация Docker Swarm.
- Worker-узлы успешно присоединены к кластеру.
- Собранные образы были загружены в Docker Hub.
- `docker-compose.yml` был адаптирован для использования образов из Docker Hub.
- Compose-файл был перенесён на manager-узел.
- Выполнен деплой стека сервисов в Swarm.
- Настроен `nginx` как прокси для доступа к:
  - `gateway service`
  - `session service`
- Прямой доступ к этим сервисам снаружи был закрыт.
- Повторно проведены тесты через Postman.
- Подтверждено успешное прохождение тестов в окружении Swarm.
- С помощью Docker-команд проверено распределение контейнеров по узлам.
- Отдельным стеком был установлен **Portainer**.
- Через Portainer проверено визуальное распределение задач по нодам.

Примеры команд:
`docker swarm init --advertise-addr <manager-ip>`  
`docker swarm join --token <token> <manager-ip>:2377`  
`docker node ls`  
`docker service ls`  
`docker stack deploy -c docker-compose.yml app`  
`docker stack services app`  
`docker stack ps app`  
`docker ps`  
`docker pull username/service:tag`  
`docker push username/service:tag`

Для nginx и сетей:
`docker network ls`  
`docker service inspect <service>`  
`curl http://localhost:port`

Для Portainer:
`docker stack deploy -c portainer-agent-stack.yml portainer`  
`docker service ls`

## Что полезно быстро повторить перед защитой

### Зачем нужен Docker Compose
`Docker Compose` нужен для запуска нескольких связанных контейнеров на одной машине.  
С его помощью удобно описывать:
- сервисы,
- сети,
- тома,
- переменные окружения,
- зависимости между контейнерами.

### Зачем нужен Docker Swarm
`Docker Swarm` нужен для оркестрации контейнеров уже не на одной машине, а на нескольких узлах.  
Он позволяет:
- распределять задачи по нодам,
- управлять сервисами как единым стеком,
- использовать overlay-сети,
- масштабировать сервисы.

### Разница между Compose и Swarm
- **Docker Compose** — запуск контейнеров на одной машине.
- **Docker Swarm** — запуск и управление сервисами в кластере из нескольких машин.

### Кто такой manager и кто такие workers
- **Manager** управляет кластером, принимает решения и запускает сервисы.
- **Worker** выполняет задачи, которые ему назначает manager.

### Зачем нужен Docker Hub
Docker Hub используется как хранилище образов.  
Это удобно, потому что в Swarm образы должны быть доступны всем узлам кластера.

### Зачем нужен Portainer
Portainer даёт веб-интерфейс для удобного просмотра:
- сервисов,
- контейнеров,
- стеков,
- сетей,
- распределения задач по нодам.
